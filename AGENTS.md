# Agent instructions

## Project
This repository contains the official website and supporting code for JD Services & Solutions, Erode.

## Workflow
- Never commit directly to `main`.
- Start every task from the latest `main` in a focused branch.
- For user-reported bugs or feature requests, create or update a GitHub Issue before implementation.
- Open a Pull Request targeting `main` and reference the issue (for example, `Closes #123`).
- Do not merge while required checks are failing.
- Do not claim a change is deployed until Render reports a successful live deployment.

## Engineering
- Inspect the existing project before changing files; preserve established conventions.
- Keep changes small, focused, accessible, responsive, and mobile-friendly.
- Validate changed files and run the available checks before opening a PR.
- Never commit secrets, credentials, private customer information, or real environment-variable values.
- Do not add paid services or incur costs without explicit user approval.
- Do not invent business details, service guarantees, prices, or customer testimonials.

## Brand details
- Business: JD Services & Solutions
- Location: Erode
- Contact: 8940454360 (label as "Call & WhatsApp" in public promotional content)
- Tagline: "Service Today... Smile Tomorrow..."
- Brand palette: deep navy, royal/electric blue, orange, yellow, and white.
- Reuse the official uploaded logo when it is available in the repository or supplied by the user. Never recreate an approximation.

## Communication
- Explain changes and risks in concise, plain language.
- Report the exact branch, PR, checks, and deployment status.
- Ask before destructive changes, production-impacting changes, or changes that create costs.
